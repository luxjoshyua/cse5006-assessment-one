Assessment criteria
Assessment 1: Frontend design and usability rubric

CRITERIA%A: 80-100%B: 70-79%C: 60-69%D: 50-59%N: <50%Frontend structure, page content and overall interface design20%Excellent frontend structure with a clear Home, About, Feeds/Posts and Settings layout. The interface is polished, logically organised and strongly supports the RSS server frontend use case. Navigation, headers, footers and page hierarchy are all well implemented. (16-20 marks)Strong frontend structure with clear page organisation and good support for the project purpose. Minor issues may exist in page hierarchy, clarity or completeness. (14-15 marks)Adequate frontend structure and page layout, but some pages or interface elements are only partially developed or inconsistently presented. (12-13 marks)Weak structure with missing or confusing pages, poor layout organisation, or limited evidence of a coherent frontend design. (10-11 marks)Little evidence of a working page structure or a usable frontend. (<10 marks)Themes and persistent user preferences15%Excellent implementation of light and dark themes with consistent styling throughout the application. Theme switching is smooth and user preferences are saved reliably using cookies or local storage. (12-15 marks)Good theme implementation with minor issues in consistency, persistence or visual quality. (11 marks)Basic theme support is present, but switching, persistence or visual consistency is incomplete or unreliable. (9-10 marks)Limited theme support with weak consistency or little evidence of saved user preferences. (7-8 marks)No meaningful theme implementation or persistence. (<7 marks)Usability, accessibility (WCAG-informed) and responsive design across devices15%Excellent responsive navigation with a working hamburger or kebab menu, clean animations or CSS transform effects, and strong usability on small screens. Navigation is clear and intuitive. (12-15 marks) Good responsive navigation with a functioning menu and minor issues in animation, layout or usability. (11 marks)  Basic menu implementation is present, but responsiveness, animation or usability is inconsistent. (9-10 marks)Limited or awkward responsive navigation with a weak menu implementation or poor small-screen behaviour. (7-8 marks)No effective hamburger/kebab menu or responsive navigation. (<7 marks)Interactive frontend views and sample/local data handling20%Highly effective interactive frontend with strong use of sample content, dynamic links, hide/show behaviour, breadcrumbs or similar navigation aids. The Feeds/Posts view is clear, functional and well suited to the later RSS workflow. (16-20 marks)Strong interactive frontend with good use of sample content and useful page interactions. Minor issues may exist in dynamic behaviour, clarity or completeness. (14-15 marks)Adequate interactivity, but sample data handling, dynamic views or navigation aids are only partially implemented or inconsistent. (12-13 marks)Limited frontend interactivity with weak use of sample content, poor responsiveness of views, or incomplete interaction features. (10-11 marks)Little or no meaningful interactivity or sample/local data handling. (<10 marks)Code quality, modularity and GitHub practice20%Excellent code quality with reusable components, clear separation of concerns, readable structure and strong use of Next.js/React best practices. GitHub history is well organised and professional. (16-20 marks)Good code quality and organisation with minor issues in modularity, consistency or repository practice. (14-15 marks)Acceptable code structure, but modularity, readability or repository organisation could be improved. (12-13 marks)Weak code structure, limited modularity, poor organisation or inconsistent implementation practices. (10-11 marks)Disorganised, incomplete or non-functional codebase. (<10 marks)Verbal justification and explanation of design choices10%Insightful, well-structured justification with strong explanation of design decisions, usability considerations, trade-offs and project continuity. Demonstrates excellent understanding of the frontend brief. (8-10 marks)Clear justification with good explanation of the main design decisions and some discussion of trade-offs or usability. (7 marks)Basic explanation with limited depth, limited reflection or weak linking between design and implementation. (6 marks)Minimal justification with unclear reasoning or very limited discussion of design choices. (5 marks)No meaningful justification provided. (<5 marks)
